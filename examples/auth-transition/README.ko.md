# 인증 Transition 예제

로컬 JWT·역할 판단 예제이며 HTTP 서버를 시작하지 않습니다.

## 실행

셸에서 `JWT_SECRET`을 명시적으로 설정한 뒤 실행합니다.

```sh
cargo run -p auth-transition
```

누락되거나 빈 비밀키는 실패하며 기본 키로 대체하지 않습니다. 예제에서
서명하는 테스트 토큰은 로그인·자격 증명 발급 기능이 아닙니다.

## 실제 계약

- `AuthResources`로 비밀키를 전달합니다.
- `authenticate`는 이전 신원을 제거하고 JWT 검증 후 `AuthContext`를 Bus에
  명시적으로 넣습니다. 반환값이 자동으로 Bus에 저장되는 것은 아닙니다.
- `authorize`는 admin 역할을 요구하고 컨텍스트 누락을 Fault로 반환합니다.
- `protected_handler`는 컨텍스트를 요구합니다. 위조한 Bus로 직접 호출하는
  행위는 인증 경계가 아니며, 실제 진입점은 인증 체인을 실행해야 합니다.
- 호출마다 새 Bus를 사용합니다. 로컬 보고서 정책은 복구가 완료된
  Unpersisted만 수용하고 나머지는 조정을 요구합니다.
- 선언한 시나리오와 다른 결과가 나오면 예제 자체가 오류를 반환합니다.

실제 서명 토큰, 만료 오류 분류, 고정된 인증 오류, 빈 신원·설정, 누락·잘못된
토큰, 비관리자 거절, 이전 위조 신원 대체, 컨텍스트 누락과 보고서 거절을
테스트합니다.

## 남은 릴리스 게이트

실제 HTTP 헤더 추출, 테넌트·발급자·대상 정책, 키 교체·폐기, 요청 제한,
응답 매핑·개인정보, 네이티브·고객 환경과 영속 실행 검증은 OPEN입니다.
로컬 토큰 검증은 배포 완료 증거가 아닙니다. 실제 구현은 `src/main.rs`,
`src/auth.rs`이며 schematic 모드는 구현한 체인을 내보냅니다.
